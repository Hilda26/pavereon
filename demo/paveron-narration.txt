Welcome to Paveron, a parametric insurance pool built on GenLayer StudioNet.

Paveron is not a normal policy dashboard. It is an insurance-native protocol for small, observable risks where the rules can be written as a public trigger. Instead of waiting for a manual adjuster, a user opens a coverage capsule with a public source URL, a time window, a premium, and a payout cap. The pool reserves payout capacity immediately, so the interface shows what is actually available rather than pretending the pool can cover unlimited risk.

On the first screen, the live pool dashboard shows reserve, available capacity, incident count, and active coverage. In this deployed run the contract is returning a real seeded state: twenty eight GEN in reserve, eighteen GEN available, zero incidents, and one active cover. This confirms that the frontend is reading from the Paveron contract through the API proxy instead of showing fake demo data.

The main workflow is the cover opening form. A user can top up the reserve, then define a coverage capsule. In this walkthrough I fill a cover for a freelancer flight delay payout. The trigger is parametric: pay when public airline status data shows an outbound flight arrived at least six hours late during the active coverage window. The form asks for the risk domain, region, public source URL, premium, payout cap, start time, and expiry. This is the part that makes Paveron feel like insurance: every cover has a premium, a reserved maximum payout, and a defined risk window.

The coverage atlas shows active routes in the pool. Each cover card includes the state, title, domain, region, reserved payout capacity, and source link. Reviewers can quickly see what is protected and where capital has been reserved. The existing seeded cover protects GitHub documentation availability, with ten GEN of reserved payout capacity and a public raw GitHub source as the observed signal.

Under the hood, the contract has thirteen main methods. Providers call fund reserve to add capital. Users call open cover to create a policy-like capsule. If something happens, they call file incident with public evidence. Then validators resolve the incident into a payout lane: full payout, partial payout, not covered, or inconclusive. Covers can also expire or retire, and the frontend reads pool, cover, incident, capacity, and wallet role state.
